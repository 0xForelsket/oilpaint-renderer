== Rust-planner revision spikes (planspike/spike_granularity.mjs, oilcore/src/bin/guidespike.rs)
WASM boundary cost for a planner stage (Node): 13,795 path traces as one batched call 14-23 ms vs one call per stroke
  16.5-20.9 ms -> <= 0.5 us per call (numbers + typed-array views; no JSON marshalling)
Storm Light guide compile at 600x750, Python (S.guides): total 1.9-2.8 s = target painting 53 ops 0.91-1.10 s |
  20 region rasters 0.05-0.07 s | 20 mask blurs (sigma 1.8-48 px) 0.18 s | structure tensor 0.10-0.11 s | 20 flows 0.38-0.44 s
Rust native (imgops): the same 20 mask blurs 0.75-0.82 s direct separable (cv2 is SIMD-tuned), 0.10-0.13 s with the
  downsample path for sigma >= 8 | 4-octave hashed-lattice bicubic value noise over the full 600x750 canvas 0.065 s
  -> estimate for a Rust spec compile of Storm Light: ~0.5-1 s native (noise evaluated only inside each shape's bbox),
     ~0.7-1.3 s WASM (x1.3); not measured end to end
Math library check (storm 600): Rust native with platform libm (glibc) vs Rust WASM with its built-in libm port:
  NOT identical (0.23% of pixels differ, rgb max 0.0001/255, h max 3.8e-6). With `detmath` (pure Rust, basic IEEE ops)
  native == Node == Chromium bit for bit (above). -> cross-host bit parity needs ONE pure-Rust math implementation compiled
  into every target (our detmath or the pure-Rust `libm` crate), never the platform libm; JS-side detmath is no longer needed.
